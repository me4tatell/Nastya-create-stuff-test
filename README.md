# Настя делает штучки — рабочий прототип

Статический кликабельный сайт. Подготовлен для GitHub Pages: **сборка, Node.js, npm и серверная часть не нужны**.

## Что загружать в репозиторий

Загрузите **содержимое этой папки**, а не папку целиком. Файл `index.html` должен лежать в корне репозитория:

```text
index.html       ← весь рабочий сайт
.nojekyll        ← отключает обработку Jekyll
.gitignore       ← исключения для локальных служебных файлов
README.md        ← эта инструкция
LICENSES/
  README.md
  Onest-OFL.txt
  CrazyV1-CC-BY-SA-4.0.txt
```

`index.html` содержит HTML, CSS, JavaScript, оба шрифта, перекрашенный логотип и SVG-декор. Шрифты и картинки встроены как data URI: отдельные папки `fonts`, `images` и `assets` **не нужны**. Ничего не удаляйте из длинных строк `data:...` при редактировании.

Остальные файлы — документация и лицензии; браузер их не загружает для работы сайта. Лицензионные материалы стоит сохранять вместе с проектом.

## Публикация через GitHub Pages

1. Создайте репозиторий. Для простого бесплатного сценария можно выбрать публичный. Помните: файлы публичного репозитория видны всем.
2. Загрузите **содержимое папки `prototype`** в корень репозитория и сохраните коммит в ветке `main`. При загрузке через браузер не загружайте сам ZIP: сначала распакуйте его. Скрытые `.nojekyll` и `.gitignore` тоже входят в архив.
3. Откройте **Settings → Pages**.
4. В **Build and deployment → Source** выберите **Deploy from a branch**.
5. Выберите ветку **main** и папку **/(root)**, затем **Save**.
6. Дождитесь завершения публикации. Pages покажет адрес сайта; для обычного репозитория он выглядит примерно так: `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.
7. Откройте выданный Pages адрес, а не страницу исходного HTML в репозитории. При задержке проверьте статус деплоя во вкладке Actions.

Переходы используют хеши (`#catalog`, `#fit`, `#cart`), поэтому дополнительный роутер или `404.html` не нужен. Сайт работает и из подпапки репозитория.

Последующие изменения: редактируйте `index.html`, делайте коммит в публикуемую ветку, дождитесь нового деплоя и обновите страницу.

## Как проверить локально

Можно открыть `index.html` в браузере. Для более предсказуемой работы буфера обмена и локального хранилища лучше локальный сервер:

```bash
cd prototype
python -m http.server 8000
```

Откройте `http://localhost:8000/`. Python нужен только для этого способа локального просмотра, не для GitHub Pages. На Pages сайт доступен по HTTPS.

## Что проверить после публикации

- Главная, каталог, примерочная, корзина и активное подчёркивание раздела.
- Семь карточек видов глюпиков, смена цвета и передача выбора в примерочную.
- Новый глюпик с шапочкой / без шапочки, добавление шапочки к существующему набору, подтверждение одинакового второго глюпика.
- Две открытки, выбор набора, перенос и удаление позиций.
- Количества товаров, скидка за каждые три шапочки, бесплатный держатель.
- Формирование и копирование сообщения. Если браузер запретил буфер обмена, выделите и скопируйте текст вручную.
- Мобильная версия.

Кнопка Telegram открывает **реальный** чат `https://t.me/an_sty`. Сообщение автоматически не отправляется. При тестировании отправлять его не нужно.

## Важные ограничения прототипа

- **Демо-админка публичная и не защищена.** Это экран демонстрации, а не настоящий серверный кабинет.
- Корзина, остатки, цены и изменения из демо-админки хранятся в `localStorage` данного браузера. **Изменение в демо-админке не обновляет сайт для других посетителей и не записывает данные в репозиторий.**
- Нет общего учёта заказов, серверных резервов, оплаты или автоматической отправки сообщений.
- Остатки и часть ассортимента демонстрационные. Фотографии заменены серыми заглушками.
- После переноса на GitHub Pages будет другой адрес сайта: корзина и настройки из текущего превью туда не переносятся. Это ожидаемо.
- При обновлении кода сохранённые настройки браузера могут перекрывать новые начальные данные. Если нужно начать с чистого состояния, в демо-админке есть **«Сбросить демонстрацию»**. Это удалит текущую локальную корзину и настройки.
- Юридические тексты, заявление о персональных данных и соответствие реальной инфраструктуре ещё требуют проверки. Не воспринимайте прототип как готовый к продажам магазин.

## Где редактировать

В `index.html`:

- `<style>` — стили. В конце находятся более новые переопределения; CSS пока намеренно не переработан, чтобы не изменить работающий дизайн.
- `<script>` — состояние, ассортимент и функции страниц: `home()`, `catalog()`, `fitting()`, `cart()`, `info()`, `admin()`.
- `species`, `colors`, `hats`, `initial` — демонстрационные данные.
- `state` — сохранённые настройки и корзина; ключ хранилища `glupiki-styled-v2`.
- `orderText()` — сообщение заказа.
- `<footer>` — общий подвал.

Секретные ключи, пароли и приватные данные в HTML добавлять нельзя: всё содержимое статического сайта доступно посетителю.

## Архив материалов

Рядом с рабочей папкой в исходном рабочем пространстве находится отдельная папка `archive`. **Её не нужно загружать в репозиторий сайта.** В ней сохранены референсы, актуальный MD-план, прежние версии, скрипты изменений, тесты, скриншоты и исходные файлы шрифтов. Они не нужны сайту во время работы.

Рабочий `index.html` при уборке не менялся; его контрольная сумма записана в `archive/prototype-sha256.txt`.
